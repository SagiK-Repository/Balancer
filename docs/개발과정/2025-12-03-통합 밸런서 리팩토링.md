# 2025.12.03. 통합 밸런서 리팩토링

## 프로젝트 목표

기존의 **분산 노드 구조(Multi-Node)**를 **단일 프로세스 + 멀티 스레드 구조(Native Core + ROS Bridge)**로 통합하여 성능 병목(Bit-Banging, Jitter)을 해결하는 것을 목표로 합니다.

## 아키텍처 변경 사항

| 구분 | 기존 (AS-IS) | 변경 (TO-BE) |
| :--- | :--- | :--- |
| **구조** | 3개 노드 분리 (`Sensor`, `Balance`, `Hardware`) | **단일 노드 (`IntegratedBalancer`)** |
| **데이터 흐름** | `I2C` → [Topic] → `PID` → [Topic] → `SPI` | `Shared Memory`를 통한 변수 직접 참조 |
| **제어 주기** | ROS `Rate` / `Timer` (Jitter 발생) | `clock_nanosleep` 기반 고정 주기 루프 |
| **SPI 통신** | `BitBangSPI` (Software 제어, 느림) | **Hardware SPI** (`/dev/spidev`, 빠름) |
| **우선순위** | 일반 Linux 프로세스 | **`SCHED_FIFO` (RT Priority 90)** |

## 구현 내용

### 1. 하드웨어 추상화 계층 (HAL) 최적화

#### 1.1 HardwareSPI 구현
- **파일**: `src/integrated_balancer/src/hardware_spi.cpp`
- **변경사항**:
  - `BitBangSPI` 제거
  - Linux 커널 SPI 드라이버 사용 (`/dev/spidev`)
  - `ioctl`을 사용한 하드웨어 SPI 통신
  - `std::this_thread::sleep_for` 사용하지 않음

#### 1.2 I2CController 분리
- **파일**: `src/integrated_balancer/src/i2c_controller.cpp`
- **변경사항**:
  - ROS 의존성 완전 제거
  - 순수 하드웨어 제어 로직만 포함
  - `SensorData` 구조체만 반환

### 2. Native Control Core 구현

#### 2.1 BalancerCore 클래스
- **파일**: `src/integrated_balancer/src/balancer_core.cpp`
- **기능**:
  - ROS 헤더 없이 동작하는 순수 제어 루프 매니저
  - `I2CController`, `HardwareSPI`, `MCP4921`, `PIDController` 객체들을 멤버로 포함
  - `std::atomic<float>` 타입의 공유 변수 (Target Speed, Current Angle 등)
  - `Mutex`로 보호된 상태값 업데이트

#### 2.2 Real-Time 스레드 설정
- `BalancerCore::start()` 함수에서 `pthread_create`로 제어 루프를 별도 스레드로 분리
- `sched_setscheduler`를 사용하여 해당 스레드의 정책을 `SCHED_FIFO`, 우선순위를 `90`으로 설정
- `mlockall`을 사용한 메모리 잠금 (옵션)

#### 2.3 고정 주기 루프
- `clock_gettime` & `clock_nanosleep`으로 정확히 **10ms (100Hz)** 주기 맞춤
- 제어 루프 순서:
  1. `imu.read()` (센서 읽기)
  2. `pid.compute()` (센서 주기와 동일한 dt=0.01s 고정 계산)
  3. `dac.write()` (모터 출력)

### 3. ROS Bridge 구현

#### 3.1 통합 main.cpp
- **파일**: `src/integrated_balancer/src/main.cpp`
- **구조**:
  ```cpp
  int main(int argc, char** argv) {
      ros::init(argc, argv, "balancing_robot");
      
      // 1. Native Control Core 시작 (별도 스레드에서 실행)
      BalancerCore robot;
      robot.start(); 
      
      // 2. ROS Communication Loop (메인 스레드, 10Hz)
      ros::Rate rate(10);
      
      // Subscriber: cmd_vel 등을 받아 robot 객체의 atomic 변수 업데이트
      ros::Subscriber sub = nh.subscribe("cmd_vel", ...);
      
      while(ros::ok()) {
          // Publisher: robot 객체의 상태를 읽어 토픽으로 발행
          msg.angle = robot.getCurrentAngle();
          pub.publish(msg);
          
          ros::spinOnce();
          rate.sleep();
      }
  }
  ```

## 핵심 코드 스니펫

### A. Hardware SPI 구현
```cpp
int HardwareSPI::transfer(uint8_t* tx, uint8_t* rx, int len) {
    struct spi_ioc_transfer tr = {
        .tx_buf = (unsigned long)tx,
        .rx_buf = (unsigned long)rx,
        .len = (uint32_t)len,
        .speed_hz = this->speed_hz_,
        .bits_per_word = 8,
    };
    return ioctl(fd_, SPI_IOC_MESSAGE(1), &tr);
}
```

### B. 고정 주기 루프 구현
```cpp
void BalancerCore::controlLoop() {
    struct timespec next_period;
    clock_gettime(CLOCK_MONOTONIC, &next_period);
    
    const long period_ns = 10000000;  // 10ms = 10,000,000 ns
    
    while(running_.load()) {
        // 1. 주기 계산
        next_period.tv_nsec += period_ns;
        if(next_period.tv_nsec >= 1000000000) {
            next_period.tv_nsec -= 1000000000;
            next_period.tv_sec++;
        }
        
        // 2. 제어 로직 실행
        processControl(); 
        
        // 3. 남은 시간만큼 정확히 Sleep
        clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &next_period, NULL);
    }
}
```

## 기대 효과

- **지연 시간(Latency)**: 2~5ms (Variable) → **< 0.1ms (Fixed)**
- **제어 안정성**: SPI 통신 오류 제거 및 모터 Jitter(떨림) 현상 해소
- **유지 보수**: ROS 연결성을 유지하므로 기존 Rviz, Teleop 툴 사용 가능
