## Step이 1로 떨어지지 않는 이유

### 현재 구현 방식

```cpp
// src/balance_robot_nodes/src/spi_hardware_node.cpp:1011-1014
if (new_hall_state_0 != hall_state_0_) {
    hall_count_0_++;
    hall_state_0_ = new_hall_state_0;
}
```

### 문제점

1. **홀 센서 읽기 주기**: 0.1ms (10kHz) - 매우 빠름
2. **홀 센서 상태 수**: 6개 (0~5 또는 1~6)
3. **카운트 로직**: 상태가 변했는지만 확인하고, 변했으면 +1만 증가

### +2가 발생하는 이유

1. **상태 건너뛰기**: 
   - 홀 센서 상태가 빠르게 변할 때 (예: 0→1→2)
   - 읽기 시점이 0→2 사이에 있으면, 코드는 0→2로 인식
   - 실제로는 2개의 상태 변화가 있었지만, 코드는 +1만 증가

2. **ROS 토픽 발행 주기**:
   - 홀 센서는 10kHz로 읽지만, ROS 토픽은 더 느린 주기로 발행
   - 한 번의 토픽 발행 사이에 여러 상태 변화가 누적될 수 있음

3. **노이즈/바운싱**:
   - 센서 신호가 불안정할 때 상태가 빠르게 변할 수 있음

### 해결 방안

#### 옵션 1: 상태 변화량 계산 (권장)
```cpp
// 상태 변화량을 계산하여 정확한 카운트 증가
int state_diff = calculateStateDifference(hall_state_0_, new_hall_state_0);
hall_count_0_ += abs(state_diff);
```

#### 옵션 2: 엔코더 기반 카운트 사용
- `HallSensorEncoder` 클래스가 이미 정확한 위치 계산을 수행
- `encoder_.getWheel0Position()` 등을 사용하여 더 정확한 카운트 얻기

#### 옵션 3: 읽기 주기 조정
- 홀 센서 읽기 주기를 조금 늦춰서 상태 변화를 더 정확히 감지
- 단, 너무 느리면 빠른 회전을 놓칠 수 있음

## 결론

- **현재 상태**: 대부분의 경우 +1로 정상 작동 (98%)
- **문제**: 가끔 +2가 발생 (1.5%)
- **영향**: 전체적으로는 큰 문제 없음 (평균 변화량 1.01)
- **개선 필요성**: 정밀한 제어가 필요한 경우 상태 변화량 계산 로직 개선 권장

## 역방향 모터 카운트 문제 (2025-12-03 추가)

### 문제점
- 역방향 모터 회전 시에도 홀 센서 카운트가 증가만 함
- 엔코더는 홀 센서 시퀀스 방향을 감지하지만, 모터 방향과 일치하지 않을 수 있음

### 해결 방법
- 모터 방향 정보(`motor0_direction`, `motor1_direction`)를 사용하여 엔코더 변화량을 조정
- 역방향일 때는 엔코더 변화량의 부호를 반전시켜 hall_count에 반영

### 수정 코드
```cpp
if (state_changed_1) {
    if (current_command_.motor1_direction) {
        // 정방향: 엔코더 증가 = hall_count 증가
        hall_count_1_ += encoder_diff_1;
    } else {
        // 역방향: 엔코더 변화량의 부호를 반전
        hall_count_1_ -= encoder_diff_1;
    }
}
```

- Motor1 (역방향): 대부분 증가, 가끔 감소 발생 - 부분적으로 개선됨
