## 사전 준비

### 1. 하드웨어 연결 확인

다음 하드웨어가 올바르게 연결되어 있는지 확인하세요:

- **MPU6050 (IMU 센서)**
  - I2C 버스: `/dev/i2c-1` (Jetson Nano 기본)
  - 주소: `0x68`
  - 연결: SDA, SCL, VCC, GND

- **MCP4921 DAC (모터 제어)**
  - SPI 버스: `/dev/spidev0.0` 또는 `/dev/spidev0.1`
  - CS 핀: GPIO 19 (DAC0), GPIO 20 (DAC1)
  - 연결: MOSI, MISO, SCLK, CS, VCC, GND

- **GPIO 핀**
  - Reverse0: GPIO 168
  - Reverse1: GPIO 13
  - 기타 제어 핀들

### 2. 권한 확인

하드웨어 접근을 위해 다음 권한이 필요합니다:

```bash
# 현재 사용자가 i2c, spi, gpio 그룹에 속해 있는지 확인
groups

# 속해 있지 않다면 추가
sudo usermod -a -G i2c,spi,gpio $USER
# 로그아웃 후 다시 로그인 필요
```

### 3. 디바이스 파일 확인

```bash
# SPI 디바이스 확인
ls -l /dev/spidev*

# I2C 디바이스 확인
ls -l /dev/i2c-*

# GPIO 칩 확인
ls -l /dev/gpiochip*
```

## 개별 컴포넌트 테스트

### 1. SPI 디바이스 테스트

```bash
# 빌드
cd ~/catkin_ws
catkin_make
source devel/setup.bash

# SPI 디바이스 테스트
rosrun integrated_balancer hardware_test spi /dev/spidev0.0
```

**예상 출력:**
```
=== SPI Device Test ===
Checking: /dev/spidev0.0
✅ SUCCESS: SPI device is accessible
```

**문제 해결:**
- SPI 디바이스가 없으면: Device Tree에서 SPI 활성화 필요
- 권한 오류: `sudo`로 실행하거나 사용자를 `spi` 그룹에 추가

### 2. I2C 디바이스 테스트

```bash
# I2C 디바이스 테스트
rosrun integrated_balancer hardware_test i2c /dev/i2c-1
```

**예상 출력:**
```
=== I2C Device Test ===
Checking: /dev/i2c-1
✅ SUCCESS: I2C device is accessible
```

### 3. I2C 디바이스 스캔

연결된 I2C 디바이스를 찾습니다:

```bash
rosrun integrated_balancer hardware_test scan /dev/i2c-1
```

**예상 출력:**
```
=== I2C Device Scan ===
Scanning: /dev/i2c-1
Found devices at addresses:
  ✅ 0x68
```

**참고:** MPU6050은 일반적으로 `0x68` 주소에 있습니다.

### 4. MPU6050 센서 테스트

```bash
rosrun integrated_balancer hardware_test mpu6050
```

**예상 출력:**
```
=== MPU6050 Sensor Test ===
✅ SUCCESS: MPU6050 initialized

Reading sensor data (10 samples)...
Sample 1:
  Accel: X=0.12 Y=-0.05 Z=9.81 m/s²
  Gyro:  X=0.5 Y=-0.2 Z=0.1 °/s
  Temp:  25.3 °C
...
✅ SUCCESS: MPU6050 is working correctly
```

**확인 사항:**
- 가속도계 Z축 값이 약 9.81 m/s² (중력)에 가까운지 확인
- 센서를 움직일 때 자이로 값이 변화하는지 확인

### 5. HardwareSPI 클래스 테스트

```bash
rosrun integrated_balancer hardware_test hardware_spi /dev/spidev0.0
```

**예상 출력:**
```
=== HardwareSPI Test ===
Testing: /dev/spidev0.0
✅ SUCCESS: HardwareSPI initialized

Testing SPI communication...
  Sent:    0x1 0x2 0x3 0x4
  Received: 0x0 0x0 0x0 0x0
✅ SUCCESS: HardwareSPI is working
```

**참고:** 루프백 테스트를 위해서는 MOSI와 MISO를 연결해야 합니다.

### 6. MCP4921 DAC 테스트

```bash
# DAC0 테스트 (CS 핀 19)
rosrun integrated_balancer hardware_test dac /dev/spidev0.0 19

# DAC1 테스트 (CS 핀 20)
rosrun integrated_balancer hardware_test dac /dev/spidev0.0 20
```

**예상 출력:**
```
=== MCP4921 DAC Test ===
SPI Device: /dev/spidev0.0
CS Pin: 19
✅ SUCCESS: MCP4921 initialized

Testing DAC output (0% -> 50% -> 100% -> 0%)...
Monitor DAC output voltage with multimeter
  Setting output to 0%
  Setting output to 50%
  Setting output to 100%
  Setting output to 0%
✅ SUCCESS: MCP4921 is working
```

**확인 사항:**
- 멀티미터로 DAC 출력 전압을 측정
- 0% → 0V, 50% → 약 1.65V, 100% → 약 3.3V (게인 1x 기준)

### 7. GPIO 핀 테스트

```bash
# 출력 핀 테스트
rosrun integrated_balancer hardware_test gpio 168 out

# 입력 핀 테스트
rosrun integrated_balancer hardware_test gpio 15 in
```

**예상 출력:**
```
=== GPIO Pin Test ===
Pin: 168 (Output)
Testing output (HIGH -> LOW -> HIGH)...
✅ SUCCESS: GPIO pin is working
```

## 통합 테스트

### 1. 전체 하드웨어 테스트

모든 하드웨어 컴포넌트를 한 번에 테스트:

```bash
rosrun integrated_balancer hardware_test all
```

### 2. 통합 밸런서 실행 테스트

실제 제어 루프를 실행하여 테스트:

```bash
# Real-Time 권한 설정 (필요시)
sudo setcap cap_sys_nice+ep ~/catkin_ws/devel/lib/integrated_balancer/integrated_balancer

# 실행
rosrun integrated_balancer integrated_balancer
```

**확인 사항:**
- ROS 토픽이 발행되는지 확인:
  ```bash
  rostopic list
  rostopic echo /sensor_roll
  rostopic echo /imu/data
  ```
- 제어 루프가 100Hz로 실행되는지 확인 (로그 확인)

### 3. 센서 데이터 모니터링

```bash
# 각도 데이터 모니터링
rostopic echo /sensor_roll

# IMU 데이터 모니터링
rostopic echo /imu/data

# rqt_plot으로 시각화
rqt_plot /sensor_roll/data
```

## 문제 해결

### SPI 디바이스가 없을 때

**증상:**
```
❌ FAILED: Cannot open /dev/spidev0.0
```

**해결 방법:**

1. Device Tree 확인:
   ```bash
   cat /proc/device-tree/spi@*/status
   ```

2. SPI 활성화 (Jetson Nano):
   ```bash
   sudo /opt/nvidia/jetson-io/jetson-io.py
   # 또는
   sudo /opt/nvidia/nvpmodel/nvpmodel -m 0
   ```

3. SPI 모듈 로드:
   ```bash
   sudo modprobe spidev
   ```

### I2C 디바이스가 없을 때

**증상:**
```
❌ FAILED: Cannot open /dev/i2c-1
```

**해결 방법:**

1. I2C 활성화 확인:
   ```bash
   sudo i2cdetect -y 1
   ```

2. I2C 모듈 로드:
   ```bash
   sudo modprobe i2c-dev
   ```

### MPU6050이 감지되지 않을 때

**증상:**
```
❌ FAILED: Cannot initialize MPU6050
```

**해결 방법:**

1. I2C 연결 확인:
   ```bash
   sudo i2cdetect -y 1
   # 0x68 주소에 디바이스가 보여야 함
   ```

2. 전원 공급 확인:
   - VCC: 3.3V
   - GND: 접지
   - SDA, SCL: 풀업 저항 확인

3. 주소 확인:
   - AD0 핀이 LOW: 0x68
   - AD0 핀이 HIGH: 0x69

### DAC 출력이 없을 때

**증상:**
```
❌ FAILED: Cannot initialize MCP4921
```

**해결 방법:**

1. SPI 연결 확인:
   - MOSI, MISO, SCLK 연결 확인
   - CS 핀 연결 확인

2. CS 핀 번호 확인:
   - 실제 하드웨어에 맞게 코드 수정 필요
   - `balancer_core.cpp`의 DAC 초기화 부분 확인

3. 전원 공급 확인:
   - VDD: 3.3V 또는 5V
   - VREF: 기준 전압 확인

### Real-Time 스레드 권한 오류

**증상:**
```
Failed to set Real-Time priority
```

**해결 방법:**

1. 권한 설정:
   ```bash
   sudo setcap cap_sys_nice+ep ~/catkin_ws/devel/lib/integrated_balancer/integrated_balancer
   ```

2. 또는 `/etc/security/limits.conf`에 추가:
   ```
   user soft rtprio 99
   user hard rtprio 99
   ```

3. 또는 `sudo`로 실행 (권장하지 않음)

### 제어 루프 주기가 불안정할 때

**증상:**
- Jitter 발생
- 주기가 일정하지 않음

**해결 방법:**

1. Real-Time 우선순위 확인:
   ```bash
   chrt -p <PID>
   ```

2. CPU 부하 확인:
   ```bash
   top -H
   ```

3. 인터럽트 확인:
   ```bash
   cat /proc/interrupts
   ```
