## 문제 분석

### 핵심 문제
**엔코더가 홀 센서 시퀀스 방향만 감지하고, 모터 방향과는 무관하게 작동**

1. **엔코더의 방향 감지 방식**:
   - 홀 센서 시퀀스의 진행 방향을 감지
   - `expected_next`와 일치 → 정방향 → `encoder_count++`
   - `expected_prev`와 일치 → 역방향 → `encoder_count--`

2. **문제점**:
   - 모터가 역방향으로 회전해도 홀 센서 시퀀스는 정방향으로 진행될 수 있음
   - 이는 하드웨어 배선이나 시퀀스 정의에 따라 달라짐
   - 결과적으로 엔코더는 거의 항상 증가만 함

3. **현재 해결 시도**:
   - 모터 방향 정보를 사용하여 엔코더 변화량의 부호를 반전
   - 하지만 여전히 대부분 증가만 발생

### 원인 추정

1. **엔코더 변화량이 항상 양수**:
   - 엔코더가 홀 센서 시퀀스 방향만 감지
   - 모터 방향과 관계없이 항상 정방향으로 인식
   - 결과적으로 `encoder_diff`가 항상 양수

2. **부호 반전 로직의 한계**:
   - 역방향일 때 `hall_count -= encoder_diff`를 수행
   - 하지만 `encoder_diff`가 항상 양수이므로 `hall_count`는 감소
   - 그러나 실제로는 증가가 더 많이 발생

3. **가능한 원인**:
   - 엔코더 변화량이 여러 샘플에 걸쳐 누적됨
   - 한 번의 읽기 사이에 여러 상태 변화가 발생
   - 모터 방향 정보가 제대로 전달되지 않음

## 해결 방안

### 옵션 1: 엔코더 방향 정보 직접 사용 (권장)
엔코더의 `direction_forward` 정보를 확인하고, 모터 방향과 일치하지 않으면 반전:

```cpp
bool encoder_direction_0 = encoder_.getWheel0Info().direction_forward;
bool motor_direction_0 = current_command_.motor0_direction;

if (encoder_direction_0 != motor_direction_0) {
    // 방향이 일치하지 않으면 반전
    hall_count_0_ -= encoder_diff_0;
} else {
    hall_count_0_ += encoder_diff_0;
}
```

### 옵션 2: 홀 센서 시퀀스 방향 확인
홀 센서 시퀀스가 모터 방향과 일치하는지 확인하고, 불일치 시 시퀀스를 반전

### 옵션 3: 하드웨어 배선 확인
실제 하드웨어 배선이 홀 센서 시퀀스와 일치하는지 확인

## 결론

- **현재 상태**: 방향 반전이 부분적으로만 작동
- **문제**: 엔코더가 모터 방향과 무관하게 항상 정방향으로 인식
- **해결 필요**: 엔코더의 방향 정보를 직접 확인하여 모터 방향과 비교
